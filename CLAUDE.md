## 2. Структура сайту та файлів

```
index.html                          ← головна: вибір класу (1–11)
5/index.html                        ← список тем 5 класу
5/lesson-slug/index.html            ← конкретний урок
5/lesson-slug/images/               ← фото для уроку (якщо є заготовки)
6/index.html
6/lesson-slug/index.html
7/index.html
7-morze/index.html                  ← другий курс 7 класу (за підручником Морзе)
7-morze/lesson-slug/index.html
...
labs/index.html                     ← Лабораторія: каталог незалежних вправ
labs/lab-slug/index.html            ← окрема гра / кросворд / вправа
result/index.html                   ← спільна сторінка «Результати уроку» (відкривається за посиланням від учня)
assets/lesson.css, assets/lesson.js  ← ядро уроку: спільні стилі й логіка (розділ 3)
_tools/check-lessons.py             ← перевірка уроків (не публікується: Jekyll пропускає теки з «_»)
_tools/lesson-template/index.html   ← шаблон нового уроку на ядрі (розділ 3)
```

- Кожен клас — окрема папка з номером (`5/`, `6/`, `7/`...).
- У кожній папці класу: `index.html` (список тем) + підпапка на кожен готовий урок.
- Назва підпапки уроку (`lesson-slug`) — короткий осмислений slug англійською, що відображає тему (`lesson-email-basics`, `lesson-device-security`, `lesson-smart-classroom`).
- Шлях файлу в репозиторії **точно повторює** майбутній шлях на сайті — це критично для деплою на GitHub Pages (`5/lesson-computer-systems/index.html` → `.../5/lesson-computer-systems/`).
- **Кілька курсів одного класу (різні автори підручника):** основний курс лишається в `{N}/`, додатковий — у `{N}-{автор}/` (зараз `7-morze/`). Тека, `{N}/index.html` і головна сторінка не змінюються (картка класу веде на `{N}/`), а на сторінках обох курсів під hero стоїть перемикач `.course-switch` («Тріщук, Лазарець | Морзе»). Матеріали — у `_materials/{N}-{автор}/`, `STORAGE_KEY` уроків — з префіксом `lesson7m-…`, щоб не змішувався з основним курсом. Slug-и уроків можуть збігатися з основним курсом — теки різні.
- **Індивідуальна форма навчання (7 клас):** тека `7-ind/` — спрощені версії уроків основного курсу (Тріщук) для учня, який відстає. Перемикач на сторінках усіх курсів 7 класу: «Тріщук | Тріщук (Індивідуальна форма) | Морзе». Список тем у `7-ind/index.html` — ті самі теми й **той самий порядок**, але назви скорочені й спрощені. Уроки робляться **лише на запит** вчителя, як спрощена копія готового уроку основного курсу з тим самим slug: мінімум тексту (1 речення на крок), більше гри — кроки з тостом «Крок N пройдено», «швидка гра» з серіями відповідей; нагорода — лише нейрончики (без зірок). `STORAGE_KEY` — з префіксом `lesson7i-…`.
- Жодного етапу «копіювання в outputs» немає: файли пишуться одразу на своє місце в репозиторії.

### Головна сторінка (`index.html`)
- Сітка карток класів 1–11.
- Активні класи (з хоча б одним готовим уроком) зберігаються в JS `const active = new Set([5,6,7,8,9]);` — додавати номер класу сюди одразу, як з'явився перший урок.
- Активна картка: бейдж «Готово», посилання на `${n}/index.html`.
- Неактивна: «Матеріали в розробці», без посилання.
- Під сіткою класів — широка картка «Лабораторія» (бірюзова, маскот-колба), веде на `labs/index.html`.
- Футер: два рядки — «Київ, 2026» і під ним пошта `tkachuk.igor@school131.kyiv.ua` (посилання `mailto:`, без підпису). Назви школи немає.

### Список тем класу (`{N}/index.html`)
- Картки-теми (`theme-card`) з бейджем кількості годин.
- Усередині кожної теми — пронумеровані рядки уроків (`lesson-row`): номер, назва, і праворуч або кнопка `Відкрити →` (якщо урок готовий, `link` веде на `lesson-slug/index.html`), або тег `Скоро`.
- **Дані з календарного плану очищаються перед внесенням у список:**
  - прибрати посилання на сторінки підручника;
  - прибрати «Практична робота №N», «Домашнє завдання», «Підсумкова робота...» з назв (лишити суть теми);
  - прибрати префікс «Інструктаж з БЖД.»;
  - назви тем-розділів можна скорочувати для стислості, зберігаючи зміст.
- Якщо кілька пунктів календаря об'єднано в один інтерактивний урок (наприклад, лекції 1-2-3 → один урок), усі відповідні рядки списку отримують те саме посилання `link`, щоб було видно, що це один матеріал.
- Кількість годин теми, якщо в джерелі не вказана явно, можна порахувати як кількість уроків у розділі.

### Лабораторія (`labs/`)
- Незалежні від календарного плану ігри, кросворди, інтерактивні вправи — не прив'язані до класу чи уроку.
- Каталог `labs/index.html` будується з JS-масиву `LABS`: `{ title, kind, grades, emoji, desc, link }`, де `kind` — `'game'` | `'crossword'` | `'exercise'`, `grades` — рядок («5–7», «усі класи»).
- Поки масив порожній — показується заглушка «Лабораторія відкривається»; фільтри за типом з'являються автоматично, щойно є хоч один елемент.
- Кожна вправа — окрема тека `labs/{slug}/index.html`, самодостатня, за тими ж правилами стилю (розділ 4), з посиланням «← Лабораторія» на `../index.html`. Акцентний колір розділу — бірюзовий (`--teal`, `#0E7C7A`).

## 3. Структура окремого уроку

Усі уроки побудовано на **ядрі** (`assets/lesson.css` + `assets/lesson.js`): файл уроку містить лише зміст, дані для вправ, власні віджети й колірну гаму, а спільне (HUD, облік блоків, механіки, фінальний тест, екран завершення, посилання з результатами) дає ядро. **Новий урок починати з шаблону `_tools/lesson-template/index.html`** — скопіювати в `{клас}/{lesson-slug}/index.html` і замінити все позначене «ЗАМІНИ».

Будова уроку:
1. **HUD** (будує ядро з `data-hud`): смужка прогресу (прив'язана до прокрутки) + лічильник нейрончиків.
2. **Hero**: рубрика (eyebrow), заголовок, 1–2 речення вступу, кнопка «Почати» (скрол до першого кроку), SVG-маскот.
3. **Пронумеровані кроки** (`Крок N · Назва`): коротке пояснення (1–2 речення) → одразу вправа, що закріплює саме це пояснення. Кожен наступний крок — своя вправа, бажано інший тип механіки (розділ 5).
4. **Фінальний тест** (`makeFinalQuiz`): питання по одному, «Далі»/«Завершити», «Запитання N з M».
5. **Екран завершення** (будує ядро): купка нейрончиків, діаграми «Пройдено» й «Точність», «Поділитися результатами», «← Повернутися до уроку».
6. **Футер** з назвою уроку та класом.

### Ядро уроку: як писати урок
Урок лежить рівно на два рівні нижче кореня (`{клас}/{урок}/index.html`), бо шляхи до ядра й `result/` — `../../`.

```html
<link rel="stylesheet" href="../../assets/lesson.css">
<style> :root{ --accent:…; --accent-dark:…; --accent-soft:…; } /* + стилі лише власних віджетів */ </style>
<body data-lesson="lesson8-tech-problems" data-hud="8 клас · Проблеми сучасних технологій">
  <section class="hero">…</section>
  <div class="container">
    <section class="block"><div class="step-label">Крок 1 · …</div> … <div id="step1List"></div></section>
    …
    <section class="block" id="finalQuizSection"><div class="step-label">Підсумок</div><h2>Коротка перевірка</h2><div id="finalQuiz"></div></section>
  </div>
  <footer>Урок · «…» · 8 клас</footer>
  <script src="../../assets/lesson.js"></script>
  <script> makeChoices('step1List', […]); …; makeFinalQuiz('finalQuiz', […], {summary:'Тепер ти знаєш…'}); </script>
</body>
```
- **`data-lesson`** — ідентифікатор уроку, з нього `STORAGE_KEY` = `{data-lesson}-neurons` (для курсу Морзе — префікс `lesson7m-`, індивідуальної форми — `lesson7i-`). **`data-hud`** — підпис у HUD.
- **HUD, смужку блоків, тест, екран завершення ядро будує саме** — у розмітці уроку їх немає. Не додавати в урок власний `addNeurons`, `STORAGE_KEY`, обробник прокрутки чи двигун тесту.
- **Блок** — секція з `.step-label`. Кожен блок має містити хоча б одну вправу, інакше він ніколи не стане «пройденим». Секцію без вправ (гід до практичної роботи, «Цікаво знати», «Перед стартом») позначати **`<section class="block" data-guide>`** — вона не рахується як блок.
- **Гама** — лише перевизначення змінних у `:root`: `--accent`, `--accent-dark`, `--accent-soft` (основний колір), `--label` (підписи кроків і рубрика, за замовчуванням = accent), `--bg`, `--ink`, `--ink-soft`, `--line`, `--surface`, `--note`/`--note-soft`/`--note-ink` (callout `.note`), `--sun`/`--sun-soft`/`--sun-ink` (повторення, `.trivia`), `--hud-bar` (заливка смужки HUD, можна градієнт). Власні назви кольорів уроку (`--pri`, `--gold` тощо) можна визначати поруч і посилатися на них.
- **Стилі уроку** — лише для власних віджетів; стилі механік ядра не дублювати. Перевизначати класи ядра тільки там, де урок свідомо має інший вигляд.

### Механіки ядра (глобальні функції)
| Функція | Дані | Розмітка в уроці |
|---|---|---|
| `makeChoices(id, items, {col}?)` | `[{text, opts:[…], correct, why?, hint?, logo?, pre?}]` — `logo`: файл `.svg` з `images/` або емодзі; `pre`: розмітка над запитанням (фрагмент листа); `hint`: підказка після помилки | `<div id="…"></div>` |
| `makeClassify(id, items, opts)` | ті самі картки, але спільні варіанти `opts` для всіх | `<div id="…"></div>` |
| `makeYesNo(id, items, 'Так…', 'Ні…')` | `[{text, correct:true/false, why?}]` | `<div id="…"></div>` |
| `makeMatching(poolId, listId, pairs, progressId?, bonus=2 \| onDone)` | `[{name, desc, icon?}]` | `<div class="match-pool" id="…"></div><div id="…"></div><div class="progress-line" id="…"></div>` |
| `makeSortBoard(poolId, {ключ:'idКошика'}, items, progressId?)` | `[{text, bucket:ключ}]` | `.sort-buckets` з `.bucket#id` (усередині `.bucket-title` і `.bucket-items`), `<div class="sort-pool" id="…">` |
| `makeSequence(doneId, qId, optsId, fbId, steps, finalText, onDone?)` | `steps` — правильний порядок; учень обирає «ПЕРШИМ», «ДРУГИМ»… | `<ol class="seq-done">`, `.seq-q`, `.seq-opts`, `.choice-feedback` |
| `makeFinalQuiz(id, questions, {summary, perCorrect=2})` | `[{q, opts, correct, why?}]`; `[]` — урок без тесту (кнопка «Завершити урок») | `<div id="finalQuiz"></div>` у секції «Підсумок» |
| `loadPic(id \| елемент, файл, емодзі)` | фото з `images/` або емодзі-заглушка | `<div class="pic" id="…"></div>` |
| `addNeurons(n)`, `shuffle(arr)` | нарахування нейрончиків, перемішування | — |

**Власна вправа уроку** (емулятор, галерея, гра) підключається до обліку одним рядком:
```js
const hit = trackTask(елементВправи, скількиЕлементів, максимумНейрончиків);
// на кожен правильно виконаний елемент:
addNeurons(1); hit();          // після останнього hit() вправа сама позначається завершеною
```
Для галереї «навчись» без нейрончиків — `trackTask(grid, cards.length, 0)` і `hit()` на перший переворот кожної картки. Повний контроль — `stepTask(el, maxНейрончиків, елементів[, true для тесту])` → `done.item()` / `done()`.

### Що рахує ядро
- **Точність** = виконані елементи / (усі елементи + помилкові спроби); для тесту — найкращий результат; загальна — середнє по блоках. Помилку ядро бачить саме: елемент вправи отримав клас `wrong`, `wrong-try`, `wrong-flash`, `miss`, `bad` або `shake`. Тож власна вправа має позначати хибну спробу одним із цих класів.
- **Екран завершення**: купка нейрончиків (≤130×130 px), на яку зароблені нейрончики летять із лічильника HUD (після чого лічильник ховається); «← Повернутися до уроку» знову відкриває тест (перездача: нейрончики лише понад найкращий результат, бонус +3 — лише за першу спробу).
- **Посилання з результатами** — самодостатнє: `result/index.html#z=…` (JSON, стиснений `deflate-raw`, base64url; `#j=…` — без стиснення для старих браузерів). Усередині: клас, назва уроку, дата, хвилини, нейрончики, точність, блоки `[назва, пройдено, точність]` і контрольна сума cyrb53 з сіллю `SALT` — вона **має збігатися** в `assets/lesson.js` і `result/index.html`.
- **Подивитись екран завершення без проходження** — відкрити урок з `?selftest` в адресі: ядро випадково позначить блоки пройденими й нарахує нейрончики.

### Перевірка
`python3 _tools/check-lessons.py` (усі уроки) або `python3 _tools/check-lessons.py 8/lesson-tech-problems`. Скрипт відкриває урок у безголовому Chrome з `?selftest` і показує помилки JS, «Блок без завдання» й відсутній фінальний тест. **Зміна ядра зачіпає всі уроки — після неї перевіряти всі.** Додаючи в ядро нову механіку, додати її й у шаблон, якщо вона типова.

### Правила для тексту всередині кроків
- Максимум 1–2 речення пояснення на абзац.
- Якщо означується кілька термінів поспіль — **кожне означення з нового рядка**, найкраще маркованим списком (`<ul><li>`), а не одним суцільним абзацом через крапку.
- Довші переліки ознак/порад — теж списком, не реченням через кому.
- Побічні факти, застереження, нюанси — виносити в блоки-callout: `.note` (нейтральний факт), `.trivia`/`.problem-note` (важливе застереження чи проблема).
- Ніколи не відтворювати дослівні фрагменти підручника — лише переказ своїми словами.

### Розділ «Повторення» на початку уроку
Якщо урок логічно продовжує попередній — почати з короткого розділу повторення (без номера кроку, крок-лейбл «Повторення · [Назва попередньої теми]»):
- 1–2 речення нагадування, що вже вивчено.
- Одна вправа, яка **справді щось перевіряє** — перевага явно надається **зіставленню «термін ↔ пояснення»** (matching), а не примітивному сортуванню на 2 кошики, якщо термінів багато і вони різні за змістом. 2-кошикове сортування («загроза/захист») критикувалось як занадто примітивне для великої кількості різних понять.
- Якщо в новій темі є явний «попередній матеріал» з підручника — перевірити, чи він не збігається з уже готовим уроком, перш ніж писати новий із нуля.

### Немає практичного завдання, коли…
Для офлайн-групових/творчих завдань (Canva-інфографіка, командний проєкт з презентацією, парне листування між учнями) — **не** намагатись гейміфікувати все у клацання. Два варіанти:
- Окрема сторінка-інструкція без нейрончиків: заголовок, картки-кроки (`guide-card`), чекліст самоперевірки, за потреби `@media print` для друку.
- Або короткий не гейміфікований розділ «Гід» у кінці самого уроку (після інтерактивної частини) — назва проєкту, потрібні інструменти, вимоги до презентації. Така секція — `<section class="block" data-guide>`, щоб ядро не чекало в ній вправи.
Якщо вчитель каже, що сам додасть практичне завдання — не писати його заздалегідь.

## 4. Підходи до стилю та дизайну

### Базова система
Змінні за замовчуванням задає `assets/lesson.css` (фіолетово-бірюзова гама: `--accent:#6C5CE7`, `--bg:#F6F5FB`, `--ink:#1B1B3A`, `--line:#E4E1F5`…, радіуси `--radius-s/m/l` = 10/16/26 px). Урок перевизначає лише потрібне (розділ 3).
Шрифти: `Baloo 2` (заголовки, лейбли, кнопки, цифри) + `Nunito Sans` (основний текст) через Google Fonts — `<link>` у `<head>` кожного уроку.

### Варіювати дизайн між уроками
Щоб уроки не виглядали як копії одне одного — **міняти акцентну палітру** для різних тем (наприклад, для теми безпеки/загроз використана малиново-золота гама `#A32D6B`/`#E8A33D` замість типової фіолетово-бірюзової). Структура компонентів і клас-неймінг лишаються тими самими — змінюється лише колірна тема й, за бажанням, маскот.

### Маскот
Простий плоский SVG у hero-блоці, тематично пов'язаний з темою уроку (нейронна мережа-візерунок, робот з «пікселізованим обличчям» у стилі підручника, комп'ютер/сервер тощо). Малювати власноруч через прості фігури (`rect`, `circle`, `path`), не використовувати растрові зображення для маскота.

### Іконка нейрончика
Стилізований біологічний нейрон: коло-сома + 6 радіальних відростків із синаптичними кружечками на кінцях, жовтий (`#FFC93C`). Розмітка — константа `NEURON_SVG` в ядрі (лічильник HUD, купка, сторінка результатів); в уроці її не повторювати.

### Фото та заготовки картинок
Якщо вправі бракує гарного фото (а не просто емодзі-іконки) — контейнер `<div class="pic" id="picX"></div>` і виклик `loadPic('picX', 'file.jpg', '📷')` (функція ядра): поки файлу немає в `images/` уроку, показується емодзі-заглушка. Розмір і пропорції `.pic` урок задає своїми стилями.
- Після побудови уроку — дати користувачу **чіткий список файлів** (назва + що зобразити), щоб він сам поклав фото в `images/` теки уроку.

## 5. Каталог типів інтерактивних вправ

Використовувати різні механіки в межах одного уроку (не повторювати той самий тип два рази поспіль). Механіки з функцією в дужках є в ядрі (розділ 3); решта — власні віджети уроку, підключені через `trackTask` (зразки — в уже готових уроках, напр. memo — `5/lesson-computer-systems/`, емулятори — `8/lesson-device-security/`, `7/lesson-cloud-services/`).

| Механіка | Опис | Коли використовувати |
|---|---|---|
| **classify-card** (`makeChoices`, `makeClassify`) | Сценарій + кнопки 2–4 варіантів відповіді | Проста класифікація понять |
| **Так/Ні варіант** (`makeYesNo`) | Те саме, але бінарний вибір | Чи це приклад X? Чи це безпечно? |
| **sort-board / кошики** (`makeSortBoard`) | Клац на чип → клац на кошик (2 або більше кошиків) | Розкласти приклади на категорії |
| **matching / зіставлення** (`makeMatching`) | Клац термін → клац пояснення, яке підходить | Термін ↔ означення, пристрій ↔ функція |
| **memo-match / «знайди пару»** | Повноцінна гра-пам'ять: перевернути дві картки, знайти збіг (назва + опис) | Запам'ятовування списку понять; дітям подобається |
| **flip-card галерея «навчись»** | Картка перевертається туди-назад на клац, показуючи пояснення | Спершу познайомити з новими термінами, **перед** тестуванням на них (memo-match чи matching) |
| **послідовний вибір кроку** (`makeSequence`) | «Що відбувається ПЕРШИМ?» → правильний варіант закріплюється, з'являється «ДРУГИМ?» тощо | **Кращий за** «розстав усі картки одразу» для процесів із 3+ кроками — учні плутались у варіанті «все й одразу перевір» |
| **order-pool (усі одразу)** | Клацнути картки в довільному порядку, потім «Перевірити» | Використовувати обережно, лише для дуже простих/коротких послідовностей (2-3 кроки) |
| **drag-and-drop дошка** | Нативний HTML5 DnD + клік-резерв (вибрати чип → клацнути ціль) для сенсорних екранів | Творчі/просторові задачі: сортування «правда/фейк», конструктор кімнати |
| **drag заповнення пропусків** | Перетягнути чип-відповідь у порожній слот | **Уникати текстового вводу**, де можна — краще перетягування чи клік |
| **«знайди ознаки» (клікабельні фрагменти)** | Клікабельні фрагменти тексту в листі/сайті; частина — правильні (`.real`), частина — **пастки** (`.decoy`), стилізовані однаково | Ключове: пастки мають виглядати так само (пунктирне підкреслення), інакше видно відповідь заздалегідь |
| **анімація «потоку» (traveling marker)** | Маркер біжить по лінії між вузлами, текст стану оновлюється на кожному етапі | Пояснити механізм: шлях листа, фільтрація трафіку брандмауером, датчик→контролер→виконавчий пристрій |
| **live-індикатор** | Оновлюється в реальному часі під час вводу | Індикатор надійності пароля |
| **емулятор** | Складніший кастомний віджет з власною анімацією/логікою | «Показати, як це працює»: антивірус-скан, поширення вірусу мережею, конструктор класу з IoT-пристроями |
| **фінальний квіз** (`makeFinalQuiz`) | Одне питання за раз, один правильний варіант, кнопка «Далі» | Завжди наприкінці уроку |

### Критичний баг, якого варто уникати
Ядро вже містить правильні стилі `.flip-card`/`.flip-inner`/`.flip-face`/`.flip-back`. Якщо урок пише власні flip-картки з іншими класами: `.flip-back` **обов'язково** повинен мати `transform: rotateY(180deg)` в CSS, окрім `.flip-inner.flipped{transform:rotateY(180deg)}`. Без цього обидві сторони картки повертаються синхронно з батьківським елементом і жодна не опиняється обличчям до глядача — картка виглядає так, ніби «зникає» після перевороту.

```css
.memo-card .flip-back{
  border:2px solid var(--card-c, var(--line));
  background:var(--card-c-light, #F0EFF9);
  transform:rotateY(180deg); /* без цього рядка — баг */
}
```

## 6. Система прогресу «нейрончики»

Нейрончики веде ядро: `addNeurons(n)` оновлює лічильник HUD і зберігає прогрес у `window.storage` під ключем `{data-lesson}-neurons`.
- Типові нарахування: **+1** за правильну відповідь у звичайній вправі; **+2…+3 бонус** за завершення всієї вправи (усі пари/усі кошики заповнено); **+2** за правильну відповідь у фінальному тесті; **+3** за його завершення. Механіки ядра нараховують так самі; власна вправа — викликом `addNeurons`.
- Максимум нейрончиків уроку ядро рахує з `trackTask`/`stepTask` (третій аргумент `trackTask`) — він потрібен для рядка «Нейрончики: X з Y» у результатах, тож указувати чесно.
- HUD-смужка прогресу прив'язана до прокрутки сторінки, не до кількості нейрончиків.

> **Увага — відомий технічний борг.** `window.storage` існує лише в середовищі артефактів Claude, у звичайному браузері його немає. На GitHub Pages збереження мовчки не працює: після перезавантаження нейрончики обнуляються. Виправлення — `localStorage` — тепер робиться в одному місці (`saveProgress`/`loadProgress` у `assets/lesson.js`), але свідомо відкладене (розділ 10).

## 7. Уроки якості й типові зауваження від вчителя

Врахувати одразу під час побудови нових уроків:

1. **Не давати підказку словом-збігом.** Якщо в питанні-сценарії буквально звучить те саме слово (чи корінь), що й у правильному варіанті відповіді — це вгадується без розуміння. Переписувати сценарій так, щоб зв'язок доводилось вивести логічно, а не впізнати за словом.
2. **«Навчи, потім перевір».** Якщо вводиться кілька нових незнайомих термінів (типи шкідливого ПЗ, мережеві пристрої, інструменти перевірки фактів) — спочатку коротка галерея-пояснення (flip-картки чи завжди видимі картки), і лише потім вправа на перевірку (memo-match або matching). Не можна одразу тестувати незнайомі терміни.
3. **Не переобтяжувати «розстав усе й перевір».** Для послідовностей від 4 кроків — краще покроковий вибір з негайним фідбеком (розділ 5), а не «постав усі 4, тоді дізнаєшся, що не так».
4. **Не видавати творчі рамки за єдину правильну відповідь**, якщо контент — реальний проєкт/творче завдання: там доречніший емулятор-конструктор (вільне розміщення, без «правильно/неправильно»), а не quiz-механіка.
5. **Дотримуватись точних формулювань вчителя.** Якщо він просить конкретне редагування тексту («заміни на...», перейменуй пункт) — вносити дослівно, без імпровізацій.
6. **Після кожної суттєвої зміни — дати шлях до файлу й відкрити його в браузері** (`open <шлях>`), щоб вчитель одразу побачив актуальну версію, а не описану словами.
7. **Завжди перевіряти баланс** `<div>`/`</div>`, `<section>`/`</section>` швидким скриптом і запускати `_tools/check-lessons.py` перед тим, як віддавати урок на перегляд.
8. Якщо тема, яку просять розробити, **вже покрита готовим уроком** (навіть під іншим формулюванням номера теми) — не дублювати, а розширити наявний урок (наприклад, додати розділ повторення).
9. Авторське право: жодних дослівних фрагментів підручника — лише переказ.

## 9. Робочий процес у Claude Code

Домовленості про те, як ведеться робота (замінюють старий чат-воркфлоу з `outputs`/`present_files`):

- **Файли пишуться одразу в репозиторій** за фінальним шляхом. Проміжні скрипти (перевірка балансу тегів тощо) — у тимчасову теку сесії, не в репозиторій.
- **Git: не комітити самовільно.** Після готового уроку чи правки — сказати «готово» й дати шлях. `git add`/`git commit` виконувати **лише на явне прохання вчителя**; `git push` — окремо й теж на прохання.
- **Перегляд результату:** відкривати готовий файл командою `open <шлях>` — вчитель дивиться в звичайному браузері. Локальний сервер не потрібен: усі шляхи всередині уроку відносні й працюють із `file://`.
- **Матеріали-джерела** лежать у `_materials/{клас}/` — підручники (PDF), календарні плани, заготовки. Тека в `.gitignore`: GitHub Pages публікує весь вміст репозиторію, тож підручники туди потрапити не можуть.
- **Підручники читати тільки через текстовий витяг.** Читання PDF напряму рендерить кожну сторінку як картинку (~1–2 тис. токенів за сторінку, максимум 20 за раз) — на 200-сторінковому підручнику це непридатно. Замість цього один раз на підручник:
  ```
  pdftotext -layout _materials/5/pidruchnyk-5.pdf _materials/5/pidruchnyk-5.txt
  ```
  Вивід **обов'язково** у файл, не в термінал. Далі з `.txt` брати лише потрібний діапазон сторінок (`sed -n '120,180p'`) або шукати `grep`-ом. Нумерація сторінок у `.txt` збігається з PDF, тож посилання календарного плану («с. 34–37») працюють напряму. Порожній `.txt` = сканований підручник, потрібен OCR.
- **Спільне — в ядрі** (`assets/`, розділ 3): урок містить лише свій зміст, дані й власні віджети. Виправлення в механіках, HUD, тесті чи екрані завершення робиться один раз — у ядрі, після чого `_tools/check-lessons.py` для всіх уроків.

## 10. Технічний борг і відкриті питання

Зафіксовано, щоб не загубилось; поточний пріоритет — контент, не рефакторинг.

1. **Прогрес не зберігається на живому сайті** (`window.storage`, розділ 6). Рішення — `localStorage` у `assets/lesson.js` (одне місце для всіх уроків). Відкладено свідомо.
2. **Власні віджети уроків** (memo, емулятори, галереї) ще дублюються між уроками в трохи різних варіантах. Якщо якийсь знадобиться в новому уроці втретє — переносити його в ядро.
3. **Назва бренду** остаточно не обрана («Пізнайко», «Іскринка»).
4. **Контрольна сума посилань із результатами захищає лише від випадкових правок**: сіль лежить у коді сторінки, тож учень, який знає JS, може підробити посилання.
